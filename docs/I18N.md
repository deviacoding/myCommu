# Module multilingue (i18n)

Le module est dans `src/i18n/`. Il sert au mode démo et servira tel quel à l'application réelle.

## Langues

| Code | Langue | Sens | Format des dates |
|------|--------|------|------------------|
| `fr` | Français (référence) | gauche → droite | `fr-FR` |
| `en` | English | gauche → droite | `en-GB` |
| `he` | עברית | droite → gauche | `he-IL` |
| `ar` | العربية | droite → gauche | `ar-u-nu-latn` (chiffres latins) |

- **Au premier lancement**, l'application prend la langue de l'appareil ou du navigateur. Si cette langue n'est pas gérée, elle s'affiche en français.
- **Ensuite**, le choix de l'utilisateur est mémorisé dans AsyncStorage, sous la clé `mycommu.lang`.
- **Où changer la langue** : écran de connexion, espace responsable et Mon compte → Préférences, via `<LanguagePicker />`.

## Utilisation dans un écran

```tsx
import { useI18n } from '../../i18n';

const { t, lang, rtl, setLang } = useI18n();

<Text>{t('rav.answers')}</Text>
<Text>{t('join.welcome', { name: firstName })}</Text>   // « Bienvenue {name} »
```

### Vocabulaire propre à chaque religion

Chaque religion a son propre vocabulaire (rabbin, imam, prêtre ou enseignant ; fidèles ; dvar Torah…). Il est rangé sous `religions.<id>.*` :

```tsx
const r = (k: string) => t(`religions.${community}.${k}`);
r('leader');        // Rabbin / Imam / Prêtre / Enseignant
```

## Règles

1. **Aucun texte d'interface en dur.** Tout texte visible passe par `t()`.
2. **`locales/fr.ts` est la source de vérité.** Toute nouvelle clé y est ajoutée d'abord. Les autres langues sont partielles (`DeepPartial`) : une clé absente s'affiche en français, donc on n'est jamais bloqué.
3. **Les clés sont groupées par écran ou par domaine** : `common`, `auth`, `demo`, `rav`, `affiliation`, `create`, `join`, `account`, `tabs`, `religions`. Leurs noms sont en anglais et en camelCase, par exemple `rav.answersPending`.
4. **Les variables s'écrivent entre accolades**, par exemple `{count}` ou `{name}`. On ne construit jamais une phrase en collant des morceaux traduits, car l'ordre des mots change d'une langue à l'autre.
5. **Dates et montants** : on passe par `utils/time.ts` (`formatLong`, `formatShort`, `money`…), qui suit automatiquement la langue grâce à `Intl`. On n'utilise pas `toLocaleDateString('fr-FR')` en dur.
6. **Droite à gauche (RTL)** :
   - On utilise `start` et `end`, `paddingStart` et `paddingEnd`, `marginStart` et `marginEnd` plutôt que `left` et `right`.
   - Les flèches et chevrons s'inversent avec `rtl`, par exemple `rtl ? 'chevron-back' : 'chevron-forward'`.
   - Sur le web, `document.dir` est réglé automatiquement.
   - Sur mobile, il faudra appeler `I18nManager.forceRTL` et redémarrer l'application quand on passe à l'hébreu ou à l'arabe (à faire lors du passage aux builds natifs).
7. **Le contenu publié n'est pas traduit par l'interface.** Dvar Torah, réponses, annonces, noms de communautés, courants et groupes créés par les utilisateurs restent dans la langue de leur auteur.

## Ajouter une langue

1. Copier `src/i18n/locales/en.ts` vers `locales/xx.ts`, puis traduire.
2. L'ajouter à `LANGUAGES` (nom natif, `rtl`, `dateLocale`) et à `DICTIONARIES` dans `src/i18n/index.tsx`.
3. Ajouter `'xx'` au type `Lang`.

## Passage au « vrai » code (backend)

- **Profil utilisateur** : stocker `preferredLang` côté serveur, pour que la langue suive l'utilisateur d'un appareil à l'autre et pour envoyer les notifications push dans sa langue. Les notifications sont traduites côté serveur avec les mêmes clés.
- **Contenus** : ajouter un champ `lang` à chaque publication. Cela permet de filtrer par langue ou de proposer une traduction automatique plus tard.
- **Référentiels partagés** (courants, groupes) : garder un `id` stable et un nom par langue, `name: { fr, en, he, ar }`. On affiche la langue courante, sinon le français.
- **Traduction** : quand le volume grandira, on pourra brancher un outil de traduction collaboratif (Crowdin, Lokalise…) sur les fichiers `locales/*.ts`, en les convertissant en JSON si besoin.
